```
Q: 为什么Binder会TransactionTooLarge？

   - Intent携带大数据
   - Bundle序列化过大
   解决方案：数据持久化后只传ID，或分片传输

Q: pthreadkey资源不足怎么定位的？
A: 通过NDK Crash堆栈定位到libc的pthread_getspecific失败，
   分析是pthread_key数量超过系统限制（通常1024个），
   排查是某个库频繁创建未释放，修复后解决

   2. 无业务堆栈tombstone归因：系统堆栈无业务代码时，AI根据历史模式推断
```

## 三、Framework核心技术准备

### 3.1 ART虚拟机（核心亮点）

```
个人实践：
- 深入ART虚拟机解决PhoneWindow多线程崩溃
- 基于ART TI自研数据录制回放工具
- JavaHook实现运行时插桩

核心知识点：
1. ART vs Dalvik
   - ART: AOT编译，安装时编译为机器码
   - Dalvik: JIT编译，运行时解释执行
   - ART 7.0后引入JIT+AOT混合模式

2. ART TI (Tool Interface)
   - 类似JVM TI，提供运行时监控能力
   - 可以Hook方法入口/出口
   - 可以录制对象分配、GC事件
   - 我用它做单测数据录制

3. JavaHook实现
   - 在方法入口插桩
   - 跳转到自定义逻辑
   - 可选是否调用原方法
   - 用于热修复、监控、归因

追问准备：

Q: ART TI和JVM TI有什么区别？
A: 基本概念类似，但ART TI针对Android优化：
   - 支持ART特有的编译模式
   - 支持Android特有的GC
   - 支持Binder调用监控

Q: Hook有什么风险？
A: 1. 性能开销：每个方法多一次跳转
   2. 兼容性：不同Android版本实现不同
   3. 稳定性：Hook失败可能导致崩溃
   解决：灰度放量、降级开关、多版本适配
```

### 3.2 Binder IPC（实战经验）

```
个人实践：
- 深入Framework解决Binder TransactionTooLarge崩溃
- 文章输出：https://mp.weixin.qq.com/s/SMdveEQAgFCiR65oDgSlcw

核心知识点：
1. Binder限制
   - 一次传输最大1MB（包括所有Parcel数据）
   - 超过抛TransactionTooLargeException
   - 常见场景：Intent大数据、Bundle序列化

2. 解决方案
   - 数据持久化后只传ID
   - 分片传输
   - 使用共享内存（MemoryFile）

3. Binder原理
   - 一次拷贝：mmap在内核和用户空间共享内存
   - 安全机制：UID/PID校验
   - 面向对象：Stub/Proxy模式

追问准备：

Q: 为什么是一次拷贝？
A: 传统IPC需要两次拷贝：
   用户空间 → 内核空间 → 用户空间
   
   Binder通过mmap，在内核和目标进程用户空间共享内存：
   用户空间 → 内核（共享内存）
   目标进程直接从共享内存读取
   
   但源进程仍需拷贝到内核，所以是"一次拷贝"

Q: Intent传大图怎么处理？
A: 1. 图片保存文件，Intent只传URI
   2. 使用BitmapFactory压缩
   3. 单例+弱引用暂存
   4. 考虑用ContentProvider共享
```

### 3.3 热修复原理（SDK负责人）

```
个人实践：
- 热修复引擎负责人，主导多引擎SDK架构设计
- 搭建C++和ART虚拟机自动化测试体系
- 全公司落地

核心原理：
1. Java热修复
   - ClassLoader双亲委派：先找父加载器，再自己找
   - PathClassLoader的pathList是Dex数组
   - 将修复Dex插入数组前面，优先加载
   - ART问题：类可能已编译为机器码，需要处理

2. Native热修复
   - plt hook：替换GOT表中的函数地址
   - got hook：直接替换函数指针
   - 需要刷新指令缓存

3. 资源热修复
   - 反射调用AssetManager.addAssetPath()
   - 构建新的Resources对象
   - 需要处理缓存问题

主流方案对比：
- Tinker：全量Dex + 资源差量
- Sophix：阿里方案，即时生效
- Andfix：Native方法替换，已废弃

追问准备：

Q: ART已编译的类怎么热修复？
A: 1. 即时生效方案：Native方法替换（Andfix）
   2. 重启生效方案：替换整个Dex（Tinker）
   3. 混合方案：Sophix

   我的方案是重启生效，更稳定：
   - 下载修复Dex
   - 合并到原Dex
   - 重启后ClassLoader加载新Dex

Q: 热修复SDK架构怎么设计的？
A: 分层架构：
   ┌─────────────────────────┐
   │  PatchManager（管理层）  │
   │  - 下载、校验、应用、回滚 │
   └───────────┬─────────────┘
               │
   ┌───────────▼─────────────┐
   │  PatchEngine（抽象层）   │
   │  - 统一接口              │
   └───────────┬─────────────┘
               │
   ┌───────────▼─────────────┐
   │ Java引擎 │ Native引擎 │ 资源引擎 │
   └─────────────────────────┘

   优点：
   - 各引擎独立演进
   - 上层无感知
   - 易于扩展
```

### 4.2 ANR优化

```
个人实践：
- 抖音ANR问题防劣化和优化
- 手机QQ消息模块ANR深度优化

核心知识点：
1. ANR类型
   - Input ANR：5秒无响应（最常见）
   - Broadcast ANR：10秒（前台）/ 60秒（后台）
   - Service ANR：20秒（前台）/ 200秒（后台）

2. ANR根因
   - 主线程耗时操作（IO、网络、锁等待）
   - 主线程被其他线程阻塞
   - 系统负载过高

3. 定位方法
   - ANR traces文件：主线程堆栈
   - StrictMode：检测主线程IO
   - 自定义监控：方法耗时插桩

我的方案：

   1. 在synchronized块前后插桩
   2. 记录锁获取时间
   3. 超过阈值输出堆栈
   4. 分析锁竞争关系

   - 写操作阻塞读操作
   - 主线程读被写阻塞 → ANR

   - 写操作写入WAL文件
   - 读操作读WAL+DB，不阻塞
   - 并发性能提升，ANR减少
```

#### 7.3.3 拓扑排序深度复习

```cpp
// 拓扑排序：适用于依赖排序、任务调度

// ========== 解法1：BFS（Kahn算法）==========
vector<int> topologicalSort(int n, vector<vector<int>>& edges) {
    vector<vector<int>> graph(n);
    vector<int> inDegree(n, 0);
    
    // 建图 + 统计入度
    for (auto& e : edges) {
        graph[e[0]].push_back(e[1]);
        inDegree[e[1]]++;
    }
    
    // 入度为0的节点入队
    queue<int> q;
    for (int i = 0; i < n; i++) {
        if (inDegree[i] == 0) q.push(i);
    }
    
    vector<int> result;
    while (!q.empty()) {
        int node = q.front(); q.pop();
        result.push_back(node);
        for (int next : graph[node]) {
            if (--inDegree[next] == 0) {
                q.push(next);
            }
        }
    }
    
    // 检测环
    if (result.size() != n) {
        // 存在环，无法完成拓扑排序
    }
    return result;
}

// ========== 解法2：DFS（后序遍历）==========
vector<int> topologicalSortDFS(int n, vector<vector<int>>& edges) {
    vector<vector<int>> graph(n);
    for (auto& e : edges) {
        graph[e[0]].push_back(e[1]);
    }
    
    vector<int> state(n, 0);  // 0=未访问, 1=访问中, 2=已完成
    vector<int> order;
    
    function<bool(int)> dfs = [&](int node) {
        if (state[node] == 1) return false;  // 环
        if (state[node] == 2) return true;   // 已完成
        
        state[node] = 1;
        for (int next : graph[node]) {
            if (!dfs(next)) return false;
        }
        state[node] = 2;
        order.push_back(node);  // 后序加入
        return true;
    };
```

```cpp
class LRUCache {
private:
    int capacity;
    list<pair<int,int>> items;  // key, value
    unordered_map<int, list<pair<int,int>>::iterator> map;
    
public:
    LRUCache(int cap) : capacity(cap) {}
    
    int get(int key) {
        if (map.find(key) == map.end()) return -1;
        items.splice(items.begin(), items, map[key]);
        return map[key]->second;
    }
    
    void put(int key, int value) {
        if (map.find(key) != map.end()) {
            items.splice(items.begin(), items, map[key]);
            map[key]->second = value;
        } else {
            if (items.size() == capacity) {
                auto last = items.back();
                map.erase(last.first);
                items.pop_back();
            }
            items.push_front({key, value});
            map[key] = items.begin();
        }
    }
};

class BlockingQueue {
private:
    queue<int> q;
    mutex mtx;
    condition_variable cv;
    int capacity;
public:
    BlockingQueue(int cap) : capacity(cap) {}
    
    void put(int val) {
        unique_lock<mutex> lock(mtx);
        cv.wait(lock, [this]() { return q.size() < capacity; });
        q.push(val);
        cv.notify_all();
    }
    
    int take() {
        unique_lock<mutex> lock(mtx);
        cv.wait(lock, [this]() { return !q.empty(); });
        int val = q.front(); q.pop();
        cv.notify_all();
        return val;
    }
};

ListNode* mergeKLists(vector<ListNode*>& lists) {
    priority_queue<ListNode*, vector<ListNode*>, 
        function<bool(ListNode*, ListNode*)>> pq(
        [](ListNode* a, ListNode* b) { return a->val > b->val; }
    );
    
    for (auto* l : lists) {
        if (l) pq.push(l);
    }
    
    ListNode dummy(0);
    ListNode* cur = &dummy;
    while (!pq.empty()) {
        cur->next = pq.top(); pq.pop();
        cur = cur->next;
        if (cur->next) pq.push(cur->next);
    }
    return dummy.next;
}

class UnionFind {
private:
    vector<int> parent, rank;
public:
    UnionFind(int n) : parent(n), rank(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    
    void unite(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return;
        if (rank[px] < rank[py]) swap(px, py);
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
    }
    
    bool connected(int x, int y) { return find(x) == find(y); }
};
```
